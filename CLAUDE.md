# Invoice

A multi-company German invoicing application. Laravel 13 + Filament 5, PHP 8.4.

> [!WARNING]
> **`AGENTS.md` is generated by Laravel Boost — do not hand-edit it as your only fix.**
> It is entirely wrapped in a `<laravel-boost-guidelines>` block that
> `boost:install` (always run as `docker compose run --rm app php artisan
> boost:install`, per the container rule below) regenerates and replaces
> wholesale by regex on every run. Any fix applied only inside that block —
> "no npm/Vite build", "no Laravel Cloud", "run everything through Docker" — comes
> straight back the next time someone runs `boost:install` to recover from a bad
> state, which both the plan and the ledger for this branch name as a legitimate
> recovery step.
>
> The real fix, already applied on this branch, is a set of **override files** under
> `.ai/guidelines/` (`foundation.blade.php`, `deployments/core.blade.php`,
> `laravel/core.blade.php`, `boost/core.blade.php`, `pint/core.blade.php`,
> `pest/core.blade.php`). Laravel Boost's `GuidelineComposer` checks this directory
> for a same-path override of every vendor guideline file *before* falling back to
> its own bundled copy (see `vendor/laravel/boost/src/Install/GuidelineComposer.php`,
> `customGuidelinePath()` / `guidelinePath()`), so these files survive
> `boost:install` regeneration — this was verified by actually running
> `docker compose run --rm app php artisan boost:install --guidelines --no-interaction`
> and confirming `AGENTS.md` came back correct.
>
> If you ever need to touch AGENTS.md content again:
> - **Prefer editing the matching file under `.ai/guidelines/`**, not `AGENTS.md`
>   directly — `AGENTS.md` is a build artifact of those files (plus vendor's own
>   templates) after a `boost:install` run.
> - If you add a *new* project-specific correction that doesn't already have an
>   override file, create one at the same relative path Boost uses internally
>   (mirror `vendor/laravel/boost/.ai/<path>`) rather than editing `AGENTS.md`.
> - Re-verify after any Boost package upgrade: a new vendor guideline file with a
>   path we haven't overridden could reintroduce a host-execution or npm/Laravel
>   Cloud suggestion. Run the command above and diff `AGENTS.md`.
> - This override mechanism is the only survivable one found in `laravel/boost`'s
>   installed source. `.ai/rules/` (a *different*, `record-rule`-driven mechanism)
>   also survives regeneration but is for path-scoped, recorded decisions, not for
>   overriding a whole guideline section — don't confuse the two.

## Everything runs in Docker

Nothing is installed on the host — not PHP, not Composer, not Postgres, not WeasyPrint.
Never run `php`, `composer`, or `artisan` directly. Always go through the container:

```sh
docker compose up -d                                    # start the stack
docker compose run --rm app php artisan <command>       # artisan
docker compose run --rm app composer <command>           # composer
docker compose run --rm app ./vendor/bin/pest           # tests
docker compose run --rm app ./vendor/bin/pint           # formatting
docker compose run --rm app ./vendor/bin/phpstan analyse --memory-limit=512M
```

The app serves at http://localhost:8080.

## Decisions that are not negotiable

- **PostgreSQL only, never SQLite — including in tests.** Invoice numbering must be
  gapless, which rests on `SELECT … FOR UPDATE`. SQLite does not implement it, so a
  suite green on SQLite would prove nothing.
- **No Node.js.** There is no frontend build. Nothing should reference `@vite`.
- **Deployment target is DigitalOcean App Platform, not Laravel Cloud.** Laravel Cloud
  cannot run WeasyPrint, which this project needs to render invoices.
- **Larastan runs at level 8.** If it reports errors, fix them or baseline them —
  never lower the level.
- Money is integer cents via `brick/money`. Never floats.
